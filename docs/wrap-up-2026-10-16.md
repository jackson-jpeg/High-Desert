## 3. The pipefail hook adds the option itself

- **What it does now:**
  - When every pipeline in a command runs in the Bash tool's own shell, the
    hook sends back `set -o pipefail; <the command>` through `updatedInput`
    and tells the model in `additionalContext`. "Its own shell" includes what
    inherits the option: `$( )`, backticks, `<( )`, subshells and `eval`.
  - **It sets no `permissionDecision`.** The rewrite approves nothing:
    permission prompts, the auto-mode classifier and every other hook still
    run as before.
- **It still refuses a pipeline the prefix can't reach:** inside `bash -c`,
  a heredoc fed to a shell, `ssh` / `mac run`, `watch` or `find -exec`.
  Those start a new shell that doesn't inherit the option. The refusal says
  where to put it instead, for example `bash -c 'set -o pipefail; a | b'`.
- **Commands that already handle it pass unchanged:** ones that mention
  pipefail or use `PIPESTATUS`.
- **Tests:** `vps-tools/tests/require-pipefail.test.py`, 61 cases.
  - The real false positives and shapes that must pass.
  - 15 that must be rewritten. Each is checked for the exact prefix, for the
    note to the model, and that no `permissionDecision` is set.
  - 13 that must still be refused.
  - The rewrite run for real: `false | true` exits 1 after the rewrite and
    0 without it (the control).
  - Three hand-made breakages each made the test fail: approving the
    command, treating `bash -c` as local, and dropping the prefix.
- **Checked live in this session:** an unprefixed `false | true` reported
  exit 1, and the hook's note arrived with it.
- **Commit:** vps-tools 317e46d. Installed to `/root/.claude/hooks/`.
  `/root/CLAUDE.md` describes it.
- **One consequence, stated in the note to the model:** with pipefail on,
  `cmd | head` can exit 141 when the reader stops early.
